## 本次发布

修复 dsh-go 原生面板在 App 里一直 `ready: false`、二维码不出现的问题；同时把 App 和网页版的登录入口
统一到「插件 → 一木记账」，不再往设置首页加独立入口。

### 原因

dsh-go 桥接在 `dshGo.panel()` 里按**插件行**反查归属包（`locate()`）：它只接受裸包名（`dsh-yimu-bill`），
`name: 'dsh-yimu-bill/native'` 这样的子路径条目无法归属，注册直接抛
`dshGo: call ctx.dshGo.* as a method from a plugin context`。异常被 cordis 接住、只留在日志里，
贡献清单因此是 `ready: false` / `no-handler`，App 不显示入口，二维码也就刷不出来。

### 修复

- 面板改从主入口 `plugin.mjs` 的 `apply` 里注册（`ctx.inject(['dshGo'])`；插件行名就是包名，桥接能正确归属）。
- **App**：面板 `placement` 只保留 `"plugin"` —— dsh-go App **设置 → 插件 → 一木记账** 详情页的内嵌面板；
  对话详情「插件」页签和「全部功能」不再重复出现二维码入口。
- **网页版**：登录页同时注册在两个位置 —— **设置 → 一木记账**（`settings.section`，明显入口）
  和 **设置 → 插件 → dsh-yimu-bill** 的配置区（`plugins.bundle.config`）。网页版和 App 共用同一个
  登录控制器、同一份 DSH 凭据；网页版用的 `/api/yimu-bill/*` 路由保留。
- **App 里隐藏网页设置入口**：网页岛里检测到 App 注入的 `DshGoIsland` 通道（UA 含 `; wv` 时兜底）
  就跳过 `settings.section` 注册——App 只能把网页设置分区当网页岛打开，无法直接显示二维码，
  与其留一个打不开的入口，不如不显示。App 二维码入口统一为 **设置 → 插件 → 一木记账** 原生面板。
- **安装引导**：包描述与 README 都写明入口（App：设置 → 插件 → 一木记账；网页版：设置 → 一木记账）。
- 精简：`lib/qr.mjs` 只输出 PNG data URL（网页版二维码也用 PNG，去掉 SVG/矩阵与
  `qrcode-generator` / `jsqr` 两个依赖）；`lib/native.mjs` 只保留 `PANEL_ID` 与 `createNativePanel()`；
  `plugin.mjs` 只做装配，HTTP 适配独立到 `lib/web-api.mjs`。
- 测试覆盖（23 项）：有/无 `dshGo` 的注册路径、网页 API 路由、清单唯一 placement、
  App 与网页版都只注册在插件详情页。

### 升级

- 升级到 0.2.3 后重启一次 DSH（网页半侧 client bundle 在进程启动时扫描）：
  - dsh-go App：设置 → 插件 → 一木记账 详情页出现二维码面板；
  - DSH Web：设置 → 插件 → dsh-yimu-bill 详情页出现登录页。
- 旧版 App 不协商 `plugin` 位置时，桥接会自动退回 `session.tab`，不会丢功能（只是入口位置不同）。
- Web / 桌面端也可以直接使用 `YIMU_TOKEN` 凭据（凭据库或环境变量）。

### 备注（上游）

按 dsh-go 原生插件协议的设计意图，桥接应能处理子路径插件行；当前 `locate()` 遇到 `<pkg>/<subpath>`
会返回 undefined 并静默失败。本版先从插件侧绕过；上游修复后可再评估恢复独立行。
